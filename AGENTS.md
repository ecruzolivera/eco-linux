# eco-linux

- `install.sh` is the no-options repo entrypoint (`--help` only). It sources every `scripts/*.sh` by absolute path in lexicographic order, including `11-user-setup` before `zz-final`. Local checkouts are detected relative to the script, not the caller's working directory. Piped/standalone bootstrap clones public `master` as the normal user, restores stdin from `/dev/tty`, reports the commit and cleans only its private temporary checkout. Keep executable bootstrap logic inside `main` so Bash parses it before switching stdin. Full personal apps/user setup are automatic; known network managers are preserved and NetworkManager is enabled otherwise. SSH detection must survive sudo so remote firewall policy is preserved.
- This is an Arch installer/config repo, not a normal app package. There is no root CI, linter, or formatter config; `tests/verify-bootstrap.py` is a standalone safe verification harness.
- Do not use `install.sh` as a casual verification step. It escalates to root, installs packages, enables services, edits `/etc`, and writes into the target user's home.
- Verify with `python3 tests/verify-bootstrap.py` and `python3 tests/verify-installer.py`; the latter runs only inert installer fixtures and mocks, never real privileged modules. `python3 tests/package-coverage.py --check-repos --installed` is a read-only cached-database/inventory audit. Syntax: `bash -n install.sh lib/*.sh scripts/*.sh`. Never execute `lib/user-setup.sh` for local verification: it downloads runtimes/editor tools and installs plugins. Do not update plugins or make real model requests for tests.
- `xdg-config/` is copied into `~/.config` by `scripts/07-copy-config.sh`. Most user-facing changes belong there.
- `home-root-config/` is copied into `~/` (`.zshrc`, `.profile`, `.bashrc`, `.vimrc`, etc.) by `scripts/07-copy-config.sh`.
- `local-bin/` is copied into `~/.local/bin/` by `scripts/07-copy-config.sh`.
- `local-share/` is copied into `~/.local/share/` for Herdr patch maintenance assets and zsh completions. Copying and user bootstrap run as the target user; no recursive ownership changes to existing home directories are allowed.
- `system-config/` holds root-owned files consumed by the installer: NVIDIA env vars, SDDM session/autologin files, and the battery charge-limit unit.
- SDDM autologin into `niri.desktop` is automatic for `REAL_USER`. `scripts/04-sddm.sh` backs up changed existing autologin files alongside the destination, leaves identical files alone, refuses non-regular replacements and never edits PAM/keyring settings. NVIDIA and battery assets remain references, not automatic defaults.
- For Niri, edit `xdg-config/niri/*.kdl`, `custom-binds.kdl` and `dms/binds.kdl`; `config.kdl` is the include list. `dms/alttab.kdl`, `dms/colors.kdl`, `dms/layout.kdl`, and `dms/outputs.kdl` are auto-generated by DMS and included as `optional=true`. `dms/cursor.kdl` is an empty placeholder; `dms/windowrules.kdl` captures current user rules.
- DMS shell settings live in `xdg-config/DankMaterialShell/` (`settings.json` plus `monitors.json`, `plugin_settings.json`, `clsettings.json`, and the `recording-indicator` and `herdr-agents` plugins). Keep custom plugin payloads, enablement and bar entries in sync with the authoritative live configuration. Herdr plugin tests run with `node --test xdg-config/DankMaterialShell/plugins/herdr-agents/tests/*.test.cjs`; integration tests use an isolated offscreen Quickshell monitor and a fake Herdr Unix-socket server/CLI, never the live session. Synchronize chezmoi's source files directly rather than using its auto-commit/auto-push-enabled capture commands unless a commit/push is explicitly requested.
- `xdg-config/nvim/` has its own local `AGENTS.md`; follow that file for Neovim-specific commands and conventions.
- `xdg-config/opencode/opencode.jsonc` is native V2 global config; `cli.json` holds terminal preferences and Herdr registration. `.opencode/opencode.jsonc` only configures this repo workspace and must not be overwritten with global settings.
- Package manifests are in `packages/`; compatibility-sensitive Herdr/OpenCode AUR recipe commits are in `packages/integrations.lock`. Normal AUR review/sudo is interactive; no temporary passwordless pacman grants are allowed. Perform full upgrades, never `pacman -Sy` partial upgrades. Official-repository transactions use `--noconfirm`; AUR and pinned recipes are reviewed together and confirmed once, and preflight inspects the target user's sudo policy with `sudo -l -U` instead of refreshing an interactive prompt. The DMS provider is the current official `dms-shell` package (it owns `dms` and `dms.service`); Arch retired `dms-shell-niri`, so never re-add it.
- Personal dotfiles are managed via `home-root-config/` in this repo. chezmoi is installed and configured (`~/.config/chezmoi/chezmoi.toml`) for users who want to layer personal dotfiles on top.
- Current live files are authoritative, not this repo or chezmoi. Capture live -> repository, preserve behavior, and document only necessary portability/first-boot adjustments. Shared skills belong in `home-root-config/.agents/skills/`, not OpenCode-specific copies.
- The automatic installer deploys shipped configurations with private changed-file backups (`ECO_CONFIG_MODE=replace`). Extra/legacy paths are retained and destination directory symlinks are refused. New files retain modes and render `__HOME__`; CLI/Yazi modes are restored. The deploy helper still supports preserve/profile fixtures, but these are not installer CLI choices. Saved hardware settings are in `profiles/ernesto/` as reference assets, not automatic defaults.
- `install_aur` presets yay's housekeeping menus for this invocation only (`--answerclean None --answerdiff All --answeredit None --noremovemake`) and sets `PAGER=cat GIT_PAGER=cat` so diffs print instead of opening a pager. `makepkg --syncdeps` runs with `--noconfirm` so reviewed AUR dependency installs do not prompt. Keep at least one explicit recipe/install confirmation; do not add `--save` or disable interactive recipe review with yay `--noconfirm`. Network-heavy stages (mise, rustup, Herdr plugins, patch deploy) run under `timeout`, and the bootstrap clones with `GIT_TERMINAL_PROMPT=0` so a credential prompt can never silently block.
- Herdr patch sources and checksums must remain identical to the verified live patch; use the bundled deployer, which refuses unfamiliar integrations. Never copy runtime registries, credentials, logs, caches, backups, `node_modules/`, or nested `.git/` metadata.
- `lib/bootstrap-herdr.py` verifies reviewed revisions and refuses unfamiliar existing plugins; `lib/bootstrap-nvim.lua` restores/checks editor tools only during actual normal-user provisioning. Bootloader, snapshots, encryption and disks remain the base installation's responsibility; normal package hooks can still update boot files. Full clean-install and hardware/suspend validation are deferred.
